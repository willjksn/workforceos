# WorkforceOS public gateway

Base path: `/api/public/v1`

| Method | Path | Auth | Cache |
| --- | --- | --- | --- |
| GET | `/content` | none | `s-maxage=60, stale-while-revalidate=120` |
| GET | `/health` | none | no-store |
| GET | `/jobs` | none, rate-friendly | `s-maxage=60` |
| GET | `/jobs/[slug]` | none | short |
| POST | `/applications` | public write + rate limit + honeypot + HMAC in production | no-store |
| POST | `/inquiries` | public write + rate limit + honeypot + HMAC in production | no-store |
| POST | `/military-talent` | public write + rate limit + honeypot + HMAC in production | no-store |

Public DTOs live in `packages/public-api-contracts`. They are not Drizzle rows.

When `PUBLIC_SITE_INTEGRATION_SECRET` is set, unauthenticated public writes must send HMAC headers. In production the secret is required; unsigned writes are rejected even if the secret was forgotten. Development may omit the secret. Origin and Referer cannot skip HMAC.

Write requests must send:

- `X-PierOne-Site-Timestamp`
- `X-PierOne-Request-Id` (UUID v4, generated by the PierOne server)
- `X-PierOne-Site-Signature` = HMAC-SHA256(secret, `METHOD\nPATH\nTIMESTAMP\nREQUEST_ID\nBODY_HASH`)

`BODY_HASH` is SHA-256 of the exact raw request body bytes (JSON UTF-8 or the precise multipart bytes sent on the wire). Filename, form fields, and resume bytes are all inside those multipart bytes, so changing any of them invalidates the signature.

WorkforceOS `/careers` forms POST to `/api/careers/applications` (not the public v1 gateway). That route requires a same-app Origin/Referer as CSRF, then server-attaches HMAC and verifies it. It is a public apply channel, not a partner-authentication bypass.

Replay: duplicate `X-PierOne-Request-Id` values are rejected for 10 minutes (`rate_limit_buckets`, clock-aligned windows). Timestamp skew remains 5 minutes.

The PierOne website should call public v1 write endpoints from its server (`sites/pierone/app/api/*`), not from the browser.
